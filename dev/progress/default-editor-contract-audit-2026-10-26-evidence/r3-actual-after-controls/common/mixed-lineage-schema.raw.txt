# V4 static schema contract — runtime not authorized

Every actual template field is pending. This document defines validation, not a freeze or test result.

- `finalSourceHead/finalSourceTree` identify final Git. `sourceHead/sourceTree` are equal aliases for existing UI drivers. No scalar `nativeProducer/nativeCompileOrdinal/nativeCompileExitCode` is accepted. `fullCompileOfFinalSourceTree` is false.
- `lineage.latestFullCompile` records ordinal/producerHead/sourceHead/sourceTree/exitCode/tsErrors, recordPath+recordSha256, pairManifestPath+pairManifestSha256 and rawLogPath+rawLogSha256. Actual compile10 JSON outputs map `outputPath`→`path`, `afterOutputSha256`→`sha256`, `sourceGitBlob`→`sourceBlob`, `afterOutputMode`→`nativeMode`. Modes are integer permission bits, not Git100644 strings. Record and pair may be the same immutable original JSON. Raw SHA must match both actual raw file and record.
- `lineage.targetedTestsEmitter` records actual id (`test-refresh-…`), candidate/sourceHead/sourceTree/exitCode/emittedAt, record/pair/raw paths and SHAs, driver/options/toolversion paths and SHAs, and exactly the two allowed outputPaths. Actual emitter JSON uses emittedAtUtc and normalized outputs. No successful emit, time, hash or final source is prefilled here.
- Each output has path/sourcePath/sha256/sourceSha256/sourceBlob/sourceMode/nativeMode/provenanceRef. Every compile10 member must exactly equal its immutable original pair. Both refreshed test members must exactly equal the emitter original pair. Native guard also checks current source/native bytes+modes and final Git source blob/hash. Producer Git source must match per file. Only the two allowed source-test paths may differ between actual compile10 source and final source. Common outputs are all compile10; full is an actual explicit superset and includes both refreshed tests.
- Canonical shared identity is SHA256 of canonical JSON `{finalSourceHead,finalSourceTree,outputs:sorted identity rows,lineage}`. J and E must have identical canonical identity and final lineage; E separately requires actual J completion SHA and root E authorization.
- Each lane proof includes actual rawLogPath/SHA, testedSourceHead/Tree, scope=`exact-declared-inputs-only`, pairManifestPath/SHA, pairManifestKind (`compile10` original-record adapter or `normalized` original freeze outputs), testedInputs and canonical testedInputsSha256. Tested inputs use final normalized rows, and each source/native pair must match original pair and actual tested-source Git. Original mode/blob fields, when present, must also match; current/final modes always require raw full-freeze provenance and native guard verification.
- Historical J helper/finder proof has provenanceRef=`historical-j-exact-inputs`, historicalScopeOnly=true; only its declared exact continuous inputs receive credit. NewDisconnectedResponseCore10 has provenanceRef=compile10, actualPassing=10 with all ten exact named test cases in the actual raw log and requires four fixed production plus Roster.test among its declared tested input pairs (ReadingColumn.test was not part of the new10 --run process). Whole old E11 dependency evidence cannot substitute. `targetedFullLensSuites` binds complete LensDisposeGate/Lens runs to actual emitter source and both refreshed outputs. A proof has no credit until actual executed/exit0/raw SHA/pairs/source continuity all validate.

The JS runtime gate calls this one Python validator with native reads disabled. Explicit before/after full guards perform source/native reads only after actual root authorization. No runtime validator, UI, fake, Xvfb, business test, emit or compile was executed during preparation.

Test input pairs are declared source/native provenance, never inferred loaded-module observations. Baseline confirmed the actual new10 command ran only Roster.test with grep `response recovery disconnected seat`; ReadingColumn.test had a separate full-run scope.
