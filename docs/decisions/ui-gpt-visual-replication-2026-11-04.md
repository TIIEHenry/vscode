# GPT 视觉复刻与产品密度边界

状态：当前有效。2026-11-04 用户修订， supersedes 既有把 `focusBorder` 作为产品自有界面键盘焦点必选表现的约定；保留键盘可达、读屏名称、状态语义和能力门控。

## 决定

1. **产品自有视觉全面以 GPT 为参照。**

   Conversation、Composer、Projects、Sessions、Navigator、Settings、Engine、Connection、Sources、Preview、Inspector、菜单、下拉和通知，统一采用参考图的表面层次、颜色、圆角、线性图标、轻阴影、输入框比例和控件排列。能直接复用现有主题 token 或共享组件的地方直接复用，不为每个页面另写一套观感。

2. **GPT 的 item 高度属于本项目的信息密度。**

   参考图中的列表、菜单、设置行和工具栏尺度不再自动收紧为旧的 22/24px 上限。产品自有表面按 GPT 的实际视觉比例落地；窄栏优先保留文字、状态和动作的可辨性，不为了回到旧高度而压缩或隐藏它们。

3. **文件管理器和代码编辑器保留 VS Code 原版尺度。**

   VS Code Explorer / 文件树 / 文件列表以及代码编辑器可以继续使用上游字号、行高、编辑器焦点和原生密度。该例外不扩散到项目、会话、设置、Conversation 或产品自有菜单。

4. **交互参考 GPT 的行为组织，不复制无关功能。**

   采用行尾更多菜单、语义分组、相邻子菜单、快捷键右对齐、图标 tooltip、当前上下文内完成短操作、状态常显和渐进披露。动作名称、命令归属、权限、保存门控、引擎状态和项目语义仍以本项目合同为准。

5. **产品自有界面不画焦点框描边。**

   不使用 `focusBorder`、`outline`、内描边或外圈阴影来表达产品自有控件的键盘焦点；也不在高对比主题中额外补一圈焦点框。键盘定位通过当前项背景、激活背景、文字/图标状态、光标和可展开线索表达，焦点元素仍保留完整 Tab / 方向键 / Enter / Escape 路径与 ARIA 语义。上游文件管理器和代码编辑器的原生焦点表现不受本条覆盖。

6. **输入框是主要视觉锚点。**

   Composer 使用 GPT 参考图的白色大圆角卡片、低对比边界、柔和阴影、左上占位文字和底部工具栏。左侧是加上下文，权限状态用橙色图标与文字，模型用中性灰胶囊，右侧保留真实能力提供的语音入口，最右为圆形发送钮。生成中的 Stop 留在 Inbox 右簇，不与发送钮合并（2026-11-06 用户确认回到 2026-09-28 的设计，撤回本条原写的发送位蓝色 Stop）。模型/推理强度提示采用黑色高对比浮层并显示快捷键。没有真实能力的入口继续诚实省略，不用参考图补造能力。

## 实施边界

- 颜色、圆角、图标、阴影和表面优先进入主题 token 或共享 CSS；组件只消费 `--vscode-*` 变量。
- 共享菜单的密度是菜单自身的显式 contract，不自动继承调用方的 compact 状态；只调整非语义留白，不隐藏状态、权限说明、禁用原因或键盘入口。
- 不复制 GPT 的商标、专有字体、专有图标和像素级品牌资产。
- 不用毛玻璃、装饰性大卡片或按压缩放制造“高级感”。
- 真实状态优先于截图观感：引擎离线、工具失败、取消、等待确认、Stub、禁用和保存失败都必须保持原有语义。

## 验收

- 浅色、深色和高对比主题中，产品自有控件没有焦点框描边，但键盘当前项仍可辨。
- 输入框的占位、底栏、权限、模型、推理提示、发送和真实能力门控与参考图保持同一层次；Stop 在 Inbox 右簇。
- Projects、Sessions、Settings、Engine、Sources 和菜单使用同一套 GPT 视觉语言；文件管理器与代码编辑器保留上游尺度。
- 菜单、子菜单、tooltip 和快捷键在鼠标与键盘路径下都能完成同一动作。
- 窄栏不隐藏必要状态；running、success、failed、cancelled、waiting、disabled 均可在不悬停时辨认。
